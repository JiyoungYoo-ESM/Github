# 기간 단위 계약

발주분석 V2와 V3에서 기간 길이를 전달하고 표시하는 기준은 **달력일(Calendar Day)** 이다. 이 문서는 계산식을 바꾸지 않고, 같은 숫자 `13`이 서로 다른 단위를 뜻하는 혼선을 막기 위한 응답·화면 계약이다.

## 공통 규칙

- 1주 = 7 달력일이다.
- V3의 1기 = 7 달력일 = 1주다. `기`는 V3 수요 관측 및 예측에만 사용한다.
- 달력월·달력년은 일수 환산으로 만들지 않는다. V3 시즌팩터는 별도 계약인 최근 24개 완료 **달력월**을 사용한다.
- 화면은 `일`을 먼저 쓰고, 필요한 경우 주 또는 V3 기 환산값을 괄호 안에 병기한다. 예: `35일 (5주 / 5기)`.
- 계산 중간값은 표기용으로 반올림하지 않는다.

## V2

- PL/USA 판매 통계는 13개 완료 주, 즉 91일의 **주간 판매량**으로 계산한다. `demand_avg`, `demand_sigma`의 단위는 수량/주이며, 일 단위로 나누어 바꾸지 않는다.
- HQ/OPO 판매 통계는 91개 완료일의 **일별 판매량**으로 계산한다. `demand_avg`, `demand_sigma`의 단위는 수량/일이다.
- API는 관측 기간의 `observation_window_days`와 수요 관측단위(`WEEK_7D` 또는 `DAY_1D`)를 함께 제공한다. 기존 `period_unit`, `demand_period_count`, `*_weeks` 필드는 호환성을 위해 유지한다.

## V3

- 판매 통계와 예측은 13개 완료 주, 즉 **91일 (13기 / 13주)** 의 수량/기로 계산한다. 수량/기를 수량/일로 나누어 안전재고 계산을 바꾸지 않는다.
- API의 `lead_time_days`, `review_days`가 기간 길이의 기준값이다. 주·기 값은 표시와 호환을 위한 파생값이다.
- API는 `observation_window_days=91`, `demand_grain=WEEK_7D`, `demand_grain_days=7`을 명시한다.

## 표시 예시

- V2 관측창: `91일 (13주)`
- V3 관측창: `91일 (13기 / 13주)`
- V2 리드타임: `35일 (5주)`
- V3 리드타임: `35일 (5주 / 5기)`
