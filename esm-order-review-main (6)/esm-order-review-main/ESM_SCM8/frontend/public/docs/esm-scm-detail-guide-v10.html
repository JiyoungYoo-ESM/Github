사용설명서(상세 가이드)

데이터 출처와 계산 로직 한눈에 보기

웹에 게시된 사용설명서의 화면 구성은 같은 상세판입니다. 여기서는 화면마다 이 숫자가 어디서 오는지(데이터 출처)와 계산 로직이 더해져 있습니다. 현재 운영 중인 발주 로직(버전 3 · 수요예측+계절조정, 내부 버전 v3.27) 기준이며, 계산 로직은 모두 4장에서 실제 숫자 예시와 함께 풀어서 설명합니다. 방향안(버전 4)은 아직 확정되지 않아 이 문서에 포함하지 않습니다.

1-1. 발주분석 V3

발주가 필요한 상품과 제안수량을 자동 계산해 SKU별로 검토하는 메인 화면입니다. 계산 순서 자체는 4장에서 실제 숫자로 풀어서 설명하며, 여기서는 화면 구성과 데이터 출처를 다룹니다.

매주 이 순서대로 (약 5분)

현재 비활성화 — 성분 탭은 데이터 정합성 보강을 위해 준비 중 상태로 비활성화되어 있습니다. 메뉴에 '준비 중'으로 표시되며 선택할 수 없고, 교차분석의 성분 조합 3종도 함께 빠져 있습니다.

"어떤 성분이 뜨고 있나?" — 흩어진 표기(센텔라·시카·병풀…)를 표준 성분명으로 묶어 성분 단위로 봅니다.

왜 보강이 필요한가 → SKU별로 어떤 성분이 들어있는지 알려주는 성분 마스터 데이터가 없습니다. 그래서 판매이력의 상품명 텍스트에서 성분 키워드를 찾아 표준 성분명으로 묶는 방식으로 대신해 왔습니다(예: 히알·히알루론·히알루론산 → 히알루론). 상품명에 성분이 없는 상품은 집계에서 빠지므로 '성분 미매칭 SKU'가 많을수록 순위가 실제와 다를 수 있어, 정합성 보강이 끝날 때까지 화면을 닫아 두었습니다.

3. 데이터 점검 — 데이터 진단

Quality

분류가 비어 있는 상품을 정리하는 화면. 미분류를 줄일수록 발주·분석의 모든 숫자가 정확해집니다. 주 1회 5분.

안내 → CMS 시즌/성분 분석 결과를 기준으로 점검 항목이 자동 집계됩니다. 보정값을 저장한 뒤 다시 분석하면 결과에 반영됩니다.
  1. 분류 필요 SKU → 판매는 있는데 카테고리가 없는 상품. 대분류·중분류 선택 → 선택값 저장. 판매량 순 정렬이라 상위부터.
  2. 성분 미매칭 SKU → 자동 태깅에서 성분/라인을 찾지 못한 상품 전체를 확인·정리. (성분 화면은 준비 중이지만 이 정리는 계속 유효)
  3. 권역 기준 확인 → 권역 없는 국가에 권역 지정 (0건이면 할 일 없음).
  4. 저장값은 다음 분석부터 반영 → 분석 탭에서 '분석 시작' 재실행.

4. 계산 로직 — 발주 로직 버전 3

Calculation Logic

발주분석 V3가 제안수량을 만드는 과정을 순서대로 풀어서 설명합니다. ① 수요 패턴을 분류하고 → ② 그 패턴에 맞는 방법으로 향후 수요(d_avg)와 예측오차(σ)를 구하고 → ③ 계절 영향을 반영한 뒤 → ④ 상품등급·발주 시나리오에 따라 Z·리드타임·발주주기 값을 대입해 목표재고(S) = L1+L2+L3를 만들고 → ⑤ 보유재고(IP)와 비교해 제안수량(Q)을 냅니다. 계산 대상 SKU의 범위는 ⑭에 정리했습니다. 방향안(버전 4, 미확정)은 다루지 않습니다.

이 장에서 쓰는 예시 상황 → 유럽법인(폴란드) 기준, 주력 등급, 주평균 판매량(d_avg) 100개, 예측오차(σ) 45, 계절지수 1.0. 계산 단위는 주(week, 7일)이고 1기 = 1주입니다. 발주 시나리오별 예시는 이 상품 하나를 기준으로 비교합니다. 내부 로직 버전은 v3.27입니다.
① 수요 패턴 분류 — "안정형·추세형·간헐형 중 무엇인가"
상품 성격이 다르면 같은 방법으로 예측해도 정확도가 달라집니다. 세 지표를 정해진 순서로 계산해 패턴을 자동으로 확정합니다. 계절성이 있는 상품은 계절 영향을 제거한 조정판매량으로 먼저 계산해야 합니다.
① ADI(판매간격지수) = 관측기간 ÷ 판매 발생 기간  ·  ② CV² = (σ÷평균)²  ·  ③ 추세 신호 = (8~13기 합계 − 1~6기 합계) ÷ 1~6기 합계
순서: ADI≥1.32 이고 동시에 CV²≥0.49이면 → 간헐형(Croston+SBA) 확정 (2026-09-02 확정 로직표 B, 두 조건이 모두 충족돼야 함).
둘 중 하나라도 못 넘으면 간헐형이 아니며, 추세 신호를 봅니다 → ±20% 넘으면 추세형(상승·하락 모두 HOLT+감쇠), 아니면 안정형.
추세 신호는 13기 중 7기(중간 기간)를 제외하고 앞 6기와 최근 6기만 비교합니다. CV²의 σ는 관측 13기 모집단 표준편차를 씁니다(표본식을 쓰면 0.49 경계에서 분류가 달라질 수 있어 고정).
예) ADI 1.1(기준 미달) → 추세 신호 +32% → 추세형으로 확정, HOLT+감쇠 적용
② 패턴별 예측 방법 — "d_avg를 어떻게 구하나"
세 방법 모두 과거 판매로 향후 평균 판매량(d_avg)을 추정하되, 반영하는 요소가 다릅니다.
안정형 → SES: 새 추정치 = 기존 추정치 + α(0.2) × (실제값 − 기존 추정치)
추세형 → HOLT+감쇠: 예측치(t) = ℓ(t−1) + φ(0.9)·b(t−1)  (α=0.2, β=0.1)
간헐형 → Croston+SBA: d_avg = (z ÷ p) × (1 − α(0.2)/2)  (p=판매간격, z=판매 발생 시 판매량, SBA 보정 0.9)
HOLT 감쇠계수(φ=0.9)는 매 기간 갱신에서 반영되며, 예측 시점에만 적용하면 오차가 커집니다. 성장세가 영원히 유지된다고 보지 않기 때문에, 성장 초기 SKU에 결품도 많고 성장이 꺾일 때 과잉재고도 많습니다.
추세형의 L1·L3는 단순 곱셈이 아닙니다 — HOLT는 감쇠 때문에 기간마다 예측치가 달라지므로, L1은 0~L̄ 구간, L3는 L̄~L̄+R 구간의 예측 합계로 계산하고, L2에 쓰는 주평균은 0~L̄+R 구간 합계를 기간 수로 나눈 값을 씁니다.
③ 예측오차(σ) — "표준편차가 아니라 예측오차를 쓰는 이유"
안전재고가 방어할 대상은 '판매가 평균에서 벗어나는 정도'가 아니라 '예측이 실제와 벗어나는 정도'입니다. 상품별로 예측을 산출하는 버전 3부터는 예측오차가 더 정확합니다.
표준편차 σ = √(Σ(실제−전체평균)² ÷ (n−1))  ·  예측오차 RMSE(σ) = √(Σ(실제−예측치)² ÷ n)
예) 어느 안정형 상품의 단순표준편차는 51.9개였지만 예측오차는 60.0개로 나타남 → 두 지표는 서로 다른 값을 줍니다. 안전재고 산식(→ ⑩)에는 예측오차를 대입합니다.
간헐형은 예외입니다 — Croston은 예측 잔차 대신 판매량 분산과 판매간격을 조합한 분산식으로 σ를 산출합니다(RMSE는 표시하지 않고 '–'). 판매가 드문 구간의 0을 오차로 취급하면 σ가 왜곡되기 때문입니다.
④ 계절 조정 — "성수기·비수기 영향을 어떻게 다루나"
수요 패턴 분류와 별개로 작동합니다. 어느 패턴이든 계절성이 있으면 동일하게 적용합니다.
영향 제거: 조정판매량 = 실제판매량 ÷ 계절지수S(m)  ·  재반영: L1 × f1, L3 × f2, L2의 주평균·σ × f_LR
계절지수는 성수기 2.0~2.5, 비수기 0.4 수준으로 나타납니다. 계절 영향을 제거한 값으로 예측한 뒤, 목표재고의 각 계층에 해당 구간의 계절지수를 다시 곱합니다 — f1은 리드타임 구간, f2는 발주주기 구간, f_LR은 보호기간 전체의 평균 지수입니다.
계절지수는 관리자 화면에서 자동 검증을 통과해 활성화된 버전만 참조합니다(24개월 범위, 1~12월 계수 평균 1.0, 중복·법인 일치 검증 → 1-2). 기능구분2가 없으면 같은 법인의 기능구분1 지수를 쓰고, 그마저 없으면 임의 지수로 대체하지 않고 그 SKU의 계산을 차단합니다. 관리자가 승인한 '계산 보류' 항목만 1~12월 모두 기본값 1.0(계절 가감 없음)으로 계산합니다.
⑤ 상품등급 — "주력/일반을 무엇으로 나누나"
품절 손실이 큰 상품을 두껍게 방어하기 위한 구분입니다. 매출을 내림차순 정렬해 누적 매출 90%까지가 주력, 나머지가 일반입니다(파레토 법칙 기준, 2026-09-02 승인).
누적 매출 ≤ 전체 매출의 90% → 주력  ·  그 외 → 일반
등급을 더 세분화하지 않아도, 상품별 변동성(σ)이 이미 ③의 예측오차에 SKU별로 반영되어 있어 변동성에 따른 차등은 이루어지고 있습니다.
⑥ 발주 시나리오 — "쇼티지 방어 / 현금흐름 우선"
전사 단위로 적용되는 기준이며 SKU별로 개별 판단하지 않습니다. 하나의 기준으로 Z값과 리드타임 기준값이 동시에 바뀝니다. 이전 문서의 '정책모드'와 같은 기능이며 화면 명칭이 발주 시나리오로 변경되었습니다.
쇼티지 방어: Z를 높이고 해운 리드타임  ·  현금흐름 우선: Z를 낮추고 폴란드는 철송 · 미국은 항공 리드타임
실측 결과 → 폴란드 법인 전체 SKU 포트폴리오를 대상으로 발주 시나리오를 전환한 결과, 발주 금액이 약 14.6% 감소했습니다(개별 SKU 예시의 60%보다 작은 폭이며, 등급·변동성이 SKU마다 달라 포트폴리오 평균은 더 작게 나타납니다). 단순한 계산 파라미터가 아니라 법인 단위 자금 이용과 재고 정책을 함께 조정하는 수단입니다.
본사(스킨)는 국내조달 단일 경로라 시나리오가 리드타임을 바꾸지 않고 Z만 바꿉니다.
⑦ 서비스레벨(Z) — "등급·발주 시나리오별 Z값"
보호기간 수요가 발주치에 닿지 않을 목표 확률(Cycle Service Level)을 직접 지정한 뒤, 그 확률에 대응하는 표준정규분포 분위수를 그대로 씁니다.
PL(유럽)·USA(미주): 쇼티지·주력 Z=1.28(≈90%) · 쇼티지·일반 Z=0.84(≈80%) · 현금·주력 Z=0.52(≈70%) · 현금·일반 Z=0.25(≈60%)
HQ(스킨창고): 쇼티지·주력 0.84(≈80%) · 쇼티지·일반 0.52(≈70%) · 현금·주력 0.25(≈60%) · 현금·일반 0(≈50%)
2026-09-02 승인된 고정 정책이며, 법인별 승인 매트릭스가 없는 법인에는 교과서 기본 매트릭스가 적용됩니다(현재 서비스 중인 3개 법인은 모두 승인 매트릭스 사용). 스킨창고는 국내 조달로 리드타임이 짧아, 같은 서비스레벨이라도 더 낮은 Z값으로 충분히 방어되어 별도 표를 씁니다. 현금·일반의 Z=0은 의도적으로 0(≈50%)으로 둔 값입니다.
⑧ 발주주기(R)·SS펜스 — "언제 다시 발주 검토하나, 안전재고 상하한"
R은 목표재고의 L3 계층과 보호기간(P)에 함께 들어가는 고정 주기입니다. SS펜스는 σ·σ_L 조합이 극단적일 때 안전재고가 비현실적으로 커지거나 작아지는 것을 막습니다.
R: 스킨창고·미주법인·유럽법인 모두 4주(28일) 고정  ·  SS = MIN(MAX(SS원값, 주평균수요×펜스하한), 주평균수요×펜스상한)
SS펜스 → 스킨창고 1주~2주 · 미주법인 2주~8주 · 유럽법인 2주~10주(법인별 상이). 펜스의 기준이 되는 '주평균수요'는 계절지수(f_LR)를 반영한 주평균 수요입니다. 펜스가 항상 붙어 있으면 펜스 값 자체를 재검증해야 한다는 신호입니다.
⑨ 법인·운송수단별 리드타임(L̄)·변동성(σ_L)
보호기간(P=L̄+R)과 안전재고(L2)의 재료가 됩니다. 리드타임 자체가 매번 달라지므로, 그 변동(σ_L)을 반영하지 않으면 배송이 늦어지는 동안의 추가 수요 위험을 방어하지 못합니다.
L̄·σ_L = 직전 6개월 완료 실측의 평균·표본표준편차(일) ÷ 7 → 주 단위. 운송수단별 유효 표본 10건 이상 필요 (스킨창고는 국내조달 단일 경로라 최근 12개월 입고건을 동일 가설로 집계 → 관측기간·집계방식이 해외법인과 다름)
유럽법인 → 해운 L̄ 72.9일(σ_L 2.18주, 표본 440건) · 철송 L̄ 36.6일(σ_L 1.15주, 표본 110건) · 항공 L̄ 16.4일(σ_L 0.68주, 표본 252건). 미주법인 → 해운 30.01일 · 항공 4.48일. 스킨창고 → 국내조달 12.12일(σ_L 16.55일, 최근 12개월 입고 5,446건 기준). 이 값들은 실행 시점의 실측 스냅샷이라 분석을 다시 돌리면 갱신됩니다 — 정확한 현재값은 검토 패널의 '입고 소요기간과 검토 주기'와 엑셀 '_계산기준' 시트에서 확인하세요. 표본 10건 미만인 운송수단(트럭킹 등)은 계산 자체를 차단합니다(→ ⑫).
⑩ 목표재고(S) — "L1·L2·L3를 어떻게 더하나" (수정)
세 항목을 따로 계산해 더하는 이유는 각 항목이 서로 다른 요인을 반영하기 때문입니다(리드타임↑해운이면 L2·L3는 그대로일 수 있고, σ↑여도 L1·L3는 그대로일 수 있음). 계절지수도 계층별로 다르게 곱합니다.
P(보호기간) = L̄ + R  ·  L1 = d_avg × L̄ × f1  ·  L3 = d_avg × R × f2  ·  L2(=SS) = Z × √(P·σ² + d_avg²·σ_L²) → SS펜스 적용
목표재고 S = L1 + L2 + L3  ·  참고 ROP = L1 + L2 (발주 조건에 사용하지 않음)
*표. 발주 시나리오별 목표재고 계산 예시(d_avg=100, σ=45, 계절지수 1.0, 유럽법인 기준)*
현금흐름 우선(철송): Z 0.52 · L̄ 5.23주 · R 4주 · P=9.23주 · σ_L 1.15주 → L1 523개, SS원값 약 93개 → SS펜스 하한(2주치=200개)에 걸려 L2 200개로 보정, L3 400개 → S 1,123개 (참고 ROP 723개)
쇼티지 방어(해운): Z 1.28 · L̄ 10.41주 · R 4주 · P=14.41주 · σ_L 2.18주 → L1 1,041개, L2 약 355개(펜스 범위 내, 원값 그대로), L3 400개 → S 1,796개 (참고 ROP 1,396개)
같은 SKU인데 약 60% 차이 나는 이유는 Z와 리드타임(실제 소요일수·변동성)이 함께 움직이기 때문입니다. 해운의 리드타임 변동(σ_L 2.18주)이 철송(1.15주)보다 훨씬 커서, 쇼티지 방어는 기간이 늘어나는 효과와 변동성이 커지는 효과가 겹칩니다. 현금흐름 우선은 Z값이 낮아 SS원값(93개)이 펜스 하한(200개)에 못 미쳐 펜스가 실질적인 안전판 역할을 합니다 → Z만 보면 안전재고가 지나치게 얇아 보이지만, 실제로는 펜스가 최저 방어선을 잡아 줍니다.
이전 버전 문서와 달라진 점 — 이전에는 "L1 = d_avg × P"로 리드타임 구간과 발주주기 구간을 합쳐 표기하고 "S = L1 + L2"로 적었습니다. 현재 화면·엑셀은 두 구간을 L1(리드타임 구간)과 L3(발주주기 구간)로 분리해 표시하고 S = L1 + L2 + L3로 계산합니다. 합계 S는 동일하지만(위 예시의 1,123 / 1,796) 화면에 보이는 계층 내역이 달라졌고, 계절지수를 구간별로 다르게 적용할 수 있게 되었습니다. 또한 참고 ROP(=L1+L2)가 검토 패널·엑셀에 표시되지만 발주 조건으로는 쓰지 않습니다 — 순수 정기발주(R,S) 모델이라 매 분석마다 IP와 S를 직접 비교합니다.
⑪ 발주반영 총재고(IP)·제안수량(Q) — "몇 개 더 필요한가"
목표재고(S)에서 이미 확보된 재고(IP)를 뺀 값이 제안수량입니다. 박스단위·MOQ 반영은 아직 정책이 확정되지 않아(V3-012) 산출된 Q를 그대로 씁니다.
PL·USA: IP = 현지가용 + 본사 법인창고 가용(EU재고) + 운송중 + 입고예정  ·  HQ: IP = 현지가용 + 입고예정
입고예정 = ① 미입고 + ② PNFM확정 + ③ 입고진행중 (④ 입고완료는 제외)  ·  매 R마다 Q = MAX(0, S − IP)
예) 목표재고 S 232,656개, IP(현재고 200 + 이송중 61,956 + 미입고 0) = 62,156개 → Q = 232,656 − 62,156 = 170,500개. 발주필요금액은 Q × 상품 단가로 계산하며, 서버가 현지 통화 원값(PL=EUR, USA=USD, HQ=KRW)으로 산출하고 원화 표기는 환산 참고값입니다. 표시 수량이나 담당자 검토수량으로 금액을 재계산하지 않습니다.
① 미입고 수량은 PO 등록일 최근 30일로 좁혀서 반영합니다 → ⑬. 재고 원천의 특정 항목이 비어 있으면 0으로 적용하고 그 사실을 '재고 원천 확인'으로 알리며, 음수가 있으면 그 SKU의 계산을 차단합니다.
⑫ 계산 차단 조건 — "발주 보류·계산 차단"
근거 없는 대체값으로 계산하는 것보다, 표본이 쌓일 때까지 계산 자체를 멈추는 쪽이 더 안전하다는 판단입니다.
① 해당 운송수단의 직전 6개월 리드타임 실측 표본 < 10건  ·  ② 최근 13주 전체 판매 0  ·  ③ Croston 기준 판매 발생 완료 주 < 2개  ·  ④ 추세 판정 기준인 앞 6주 판매 합계 = 0  ·  ⑤ 계절지수 연결 불가(기능구분 미분류 또는 해당 법인 프로파일 없음/계산 실패)  ·  ⑥ 재고 원천 음수 등 입력·정책값 무효
위 조건 중 하나라도 해당하면 그 SKU는 결과를 산출하지 않고 '발주 보류·계산 차단'으로 표시됩니다. 전사 평균 등으로 대체하지 않습니다. 화면의 사유 필터는 이 조건들을 판매이력 부족 · 간헐형 계산 조건 확인 · 추세형 계산 조건 확인 · 입력 데이터·계산 조건 확인 네 그룹으로 묶어 보여줍니다.
⑬ 미입고 조회창 — "① 미입고만 PO 등록일 최근 30일" (신설 · 2026-09-04)
이전에는 미입고 현황을 연초(1월 1일)부터 전부 가져왔습니다. 그 창은 운송중 조회와 공유하던 값이라, PO 등록일이 오래된 잔량까지 계속 입고예정으로 누적돼 IP가 과대계상되고 실제로 발주가 필요한 SKU가 제안수량 0으로 판정되는 사례가 확인됐습니다.
① 미입고 수량만 PO 등록일 기준 분석 기준일 포함 최근 30 달력일(기준일−29일 ~ 기준일)로 제한  ·  ② PNFM확정 · ③ 입고진행중 · ④ 입고완료는 기간 제한 없음
②③④는 이미 입고 통보되었거나 입고가 진행 중인, 확실히 들어올 물량이므로 PO 등록일이 오래되었다는 이유로 빼지 않습니다. 창은 수량 하나만 바꾸며, SKU의 원천 행 존재 여부·상품명·바코드 등 식별 증거와 계산 모집단은 창 적용 전과 같습니다 — 상품이 분석에서 사라지지 않습니다. 운송중·재고·판매·리드타임 조회창과 발주분석 V1·V2의 조회창은 변경하지 않았습니다.

발주분석 V3는 어디서 실행하나요?발주분석 V3 화면 안의 상단 실행 상태바에서 분석 실행 / 새로 분석을 누릅니다. 발주 그룹의 '데이터 입력' 화면은 V1·V2용이며 V3와 무관합니다 (→ 1-3).
여러 명이 동시에 분석을 돌리면?서버 작업 큐에서 순서대로 처리됩니다. "사용 가능한 분석 Worker를 기다리는 중"이라고 안내되고 순서가 오면 자동 시작되며, 그동안 이전 완료 결과는 유지됩니다. 통신 지연 시 같은 분석에 자동 재연결합니다.
목표재고 공식이 이전 문서와 달라요 (S=L1+L2 → L1+L2+L3)합계 S는 동일하고 표기 방식이 바뀐 것입니다. 이전에는 L1을 보호기간(P=L̄+R) 전체 수요로 묶어 적었고, 현재는 L1(리드타임 구간)과 L3(발주주기 구간)을 분리해 표시합니다. 계절지수를 구간별로 다르게 적용하기 위한 변경이며, 화면·엑셀도 세 계층을 각각 보여줍니다 (→ 계산 ⑩).
참고 ROP는 왜 표시하면서 안 쓰나요?V3는 순수 정기발주(R,S) 모델이라 매 분석마다 IP와 목표재고(S)를 직접 비교합니다. ROP(=L1+L2)는 계층 구성을 점검하기 위한 참고값으로만 남겨 두었습니다.
제안수량이 0인데 실제로는 재고가 부족해요오래된 미입고 잔량이 입고예정으로 계속 누적되면 IP가 과대계상됩니다. 2026-09-04부터 ① 미입고 수량을 PO 등록일 최근 30일로 제한해 이 문제를 줄였습니다 (→ 계산 ⑬). 그래도 0이면 검토 패널의 '발주에 반영한 재고'에서 어떤 항목이 IP를 채웠는지 확인하세요.
금액이 안 보여요 / '[금액 제한]'으로 나와요금액 조회 권한이 없는 계정입니다. 수량·비중·점유율·순위는 그대로 보이며 엑셀의 단가·금액 열도 숨겨집니다 (→ 0-4).
'상태 확인 필요' 목록은 뭔가요?계산은 됐지만 발주 필요/불필요를 확정하지 못한 상품을 모아두는 안전장치입니다. 임의로 '불필요'로 처리하지 않기 위한 목록이며, 건수가 0이면 링크가 나타나지 않습니다.
발주 보류·계산 차단이 된 이유리드타임 표본 부족(운송수단 10건 미만), 최근 13주 판매 부족, 간헐형·추세형 계산 조건 미충족, 계절지수 연결 불가, 재고 원천 음수 등입니다 (→ 계산 ⑫). 표본이 쌓이면 자동으로 계산 대상에 포함됩니다.
계절지수는 누가 갱신하나요?관리자입니다. 자동 검증(24개월 범위·계수 평균 1.0·중복·법인 일치)을 통과한 버전만 V3에 적용되고, 실패하면 기존 버전이 유지됩니다 (→ 1-2).
발주 시나리오를 잘못 바꾸면? (Z·등급 값)시나리오 자체는 화면에서 고를 수 있지만, 그 안의 Z값·상품등급 경계는 팀이 통계적으로 확정해 둔 값이라 개별 수정할 수 없습니다 (→ 계산 ⑤~⑦).
환율은 어디서 바꾸나요?현재는 화면에서 입력하지 않습니다. 워크스페이스 진입 시 1회 자동 조회한 고시환율을 원화 환산 참고값으로 사용하며, 발주필요금액은 서버가 현지 통화 원값으로 계산합니다 (→ 0-1).
성분 탭이 비활성화되어 있어요.데이터 정합성 보강을 위해 준비 중 상태입니다. 교차분석의 성분 조합도 함께 빠져 있고, 데이터 점검의 '성분 미매칭 SKU' 정리는 계속 유효합니다 (→ 2-9).
재고 공백 화면이 안 보여요.사이드바 별도 메뉴가 아니라 발주분석 V1 화면의 하위 탭입니다 (→ 1-3).
