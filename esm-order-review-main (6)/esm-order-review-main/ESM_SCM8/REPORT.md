# ESM SCM 발주 검토 자동화 시스템 구현 현황 보고서

작성 기준: 2026-05-27 현재 코드 기준

## 1. 개요

ESM SCM 발주 검토 자동화 시스템은 유럽 법인 발주 판단에 필요한 CMS/ERP 데이터를 한 화면에서 통합 검토하기 위한 업무 보조 도구입니다.

기존에는 EU 현지 재고, 본사 EU 창고 재고, 운송중 물량, 판매 데이터, 미입고현황 등을 각각 내려받은 뒤 엑셀에서 수작업으로 연결해야 했습니다. 이 과정에서 SKU별 발주 필요 여부, 본사 재고 이동 가능 여부, 운송중 물량 도착 후 커버 가능 여부를 일관된 기준으로 빠르게 판단하기 어려웠습니다.

본 시스템의 목적은 분산된 데이터를 SKU 단위로 통합하고, 안전재고 기준 대비 부족 여부를 자동 계산하여 팀장님, BM, ESM 실무자가 같은 기준으로 발주 검토를 진행할 수 있도록 하는 것입니다.

## 2. 현재 기술 스택

| 구분 | 기술 |
| --- | --- |
| 백엔드 | Python 3.11+, FastAPI |
| 프론트엔드 | Next.js (TypeScript) |
| 핵심 분석 엔진 | core/ 패키지 (pandas 기반) |
| 실행 환경 | 로컬 PC (Windows) |

백엔드는 FastAPI로 파일 업로드 → 분석 → 엑셀 다운로드 API를 제공합니다. 프론트엔드는 Next.js로 파일 업로드, 발주 검토 결과 화면, 대시보드를 제공합니다. 기존 Streamlit 스택은 제거되었습니다.

## 3. 기존 업무상 문제

- CMS에서 필요한 데이터가 EU 현지 재고, 본사 EU 창고 재고, 판매내역상세, 운송중/해상 데이터, 미입고현황 등으로 분산되어 있습니다.
- SKU 단위로 발주 필요 여부를 판단하려면 여러 파일을 수작업으로 매칭해야 합니다.
- 전체 SKU 기준과 브랜드별 기준을 빠르게 전환하며 우선순위를 보기 어렵습니다.
- 운송중 물량, 본사 이동 가능 수량, EU 현지 가용재고를 동시에 반영하려면 엑셀 가공 시간이 많이 소요됩니다.
- 수작업 파일마다 기준일, 판매수량 기준, 제외 SKU 기준이 흔들릴 수 있습니다.
- 발주 필요, 본사 이동, 운송 도착 대기, 확인 필요 사유가 한 컬럼에 섞이면 의사결정 기준이 불명확해질 수 있습니다.

## 4. 시스템 목표

- EU 현지 재고, 본사 EU 창고 재고, 운송중 물량, 판매수량을 SKU 단위로 통합합니다.
- 최근 3개월 PA+CA 판매수량을 기준으로 월평균, 일평균, 안전재고 목표수량을 계산합니다.
- 안전재고 대비 부족 수량과 추가 발주 필요 수량/금액을 산출합니다.
- 본사 EU 창고 재고 이동으로 신규 발주 없이 커버 가능한 SKU를 구분합니다.
- 운송중 또는 미입고 물량 도착 후 커버 가능한 SKU를 구분합니다.
- 브랜드별 필터링, 운송수단별 필터링, KPI 요약, 내부 보고용 엑셀 다운로드를 제공합니다.
- 팀장님/BM/ESM 실무자가 발주 우선순위와 확인 필요 항목을 빠르게 확인할 수 있는 구조를 제공합니다.

## 5. 사용 데이터

현재 코드 기준으로 업로드 가능한 데이터는 아래와 같습니다.

| 데이터 | 주요 용도 |
| --- | --- |
| EU 현지 재고 | 기준 SKU 마스터, 브랜드/상품명/바코드, EU 현지 가용수량, EU 입고단가, 최근 3개월 PA+CA 판매수량 확인 |
| 본사 EU창고 재고 | EU 현지 부족분을 본사 EU 창고 재고 이동으로 커버할 수 있는지 판단 |
| 판매내역상세 | 판매속도 이상 감지, PA+CA 판매수량과 보조 검증용 판매수량 차이 확인 |
| 본사→유럽법인향 판매내역상세 | 공급 파이프라인 출고금액 KPI 계산 |
| 해상/운송중 데이터 | 운송중 수량 집계, ETA 계산, ETA 캘린더/타임라인 구성 |
| 미입고현황 | 미입고수량 참고 및 설정에 따라 부족수량 산정에 포함 가능 |
| 과거 판매내역 | 시즌 발주 캘린더 샘플/참고 화면 구성 |

업로드 파일이 없으면 코드 내부 샘플 데이터로 동작합니다.

## 6. 핵심 발주 판단 로직

현재 발주 검토의 기본 수요 기준은 EU 현지 재고 파일의 최근 3개월 PA+CA 판매수량입니다.

계산 흐름은 다음과 같습니다.

1. EU 현지 재고 파일을 기준 SKU 목록으로 사용합니다.
2. 최근 3개월 PA+CA 판매수량을 기준으로 월평균 판매수량과 일평균 판매수량을 계산합니다.
3. 안전재고 목표수량은 월평균 판매수량 × 안전재고 기준 개월 수로 계산합니다.
4. EU 현지 가용수량과 운송중 수량을 합산하여 현재 확보 가능한 물량을 계산합니다.
5. 미입고현황은 기본값으로 부족수량 계산에는 포함하지 않고 참고값으로 표시합니다.
6. 안전재고 목표수량 대비 부족분을 1차 부족수량으로 계산합니다.
7. 본사 EU 창고 재고를 반영하여 본사 이동 수량을 산출합니다.
8. 1차 부족수량에서 본사 이동 수량을 차감한 값을 추가 발주 필요 수량으로 계산합니다.
9. 추가 발주 필요 금액은 추가 발주 필요 수량 × EU 입고단가 × EUR/KRW 환율로 계산합니다.
10. FOC/무상/샘플/단종/판매 없음 등 제외 기준에 해당하는 SKU는 발주 수량과 금액을 0으로 보정합니다.

운송중 ETA는 현재 출고일 + 운송수단별 리드타임 기준으로 계산됩니다.

## 7. 최종 액션 분류

현재 발주 판단 결과는 `최종 액션`, `상태`, `조치 요약`, `근거`, `예외 플래그`, `예외 사유`로 분리되어 있습니다.

`최종 액션`은 원칙적으로 아래 두 값 중심으로 사용됩니다.

- 발주 필요
- 발주 필요 없음

| 상태 | 업무 의미 | 최종 액션 |
| --- | --- | --- |
| 확인필요 | SKU 미등록, 운송수단 미확인, 판매수량 차이, 데이터 오류 가능성 등 담당자 확인 필요 | 발주 필요 없음 |
| 발주제외 | FOC/무상/샘플/단종, 최근 3개월 판매 없음, 저판매 기준 미만 등 | 발주 필요 없음 |
| 본사이동 | 본사 EU 창고 재고 이동으로 신규 발주 없이 안전재고 커버 가능 | 발주 필요 없음 |
| 운송대기 | EU 현지 재고만으로는 부족하지만 운송중/미입고 물량 도착 시 커버 가능 | 발주 필요 없음 |
| 정상 | 일반 판단 대상. 추가 발주 필요 수량이 있으면 발주 필요, 없으면 발주 필요 없음 | 조건별 결정 |

## 8. 현재 구현된 주요 기능

- CSV/XLS/XLSX 파일 업로드 (FastAPI)
- 업로드 파일이 없을 때 샘플 데이터로 동작
- EU 현지 재고, 본사 EU창고 재고, 판매내역상세, 운송중, 미입고현황 등 데이터 표준화
- SKU 기준 발주 검토 결과 산출
- 최종 액션, 상태, 조치 요약, 근거, 예외 플래그 분리
- 브랜드 필터 자동 추출 및 필터링
- 운송수단 개별 체크 필터링
- 대시보드 KPI 카드 (Next.js)
- 발주 검토 시트 화면 (Next.js)
- 내부 보고용 엑셀 다운로드
- ETA 캘린더 및 ETA 타임라인
- 입고 예정 통합 시트 및 월별/운송수단별 입고 요약
- 확인필요 시트
- EUR/KRW 환율 자동 조회 (Koreaexim API)

## 10. 현재 검증이 필요한 부분

- 브랜드 하나가 아니라 유럽 법인 전체 SKU 기준으로 실행 테스트가 필요합니다.
- 전체 SKU 실행 시 속도, 메모리 사용량, 화면 응답성, 오류 발생 여부를 확인해야 합니다.
- 엑셀 다운로드 결과가 화면 필터와 일치하는지 확인해야 합니다.
- 원본 CMS 데이터와 발주 필요 수량/금액 결과값의 정합성을 추가 검증해야 합니다.
- 미입고현황을 부족수량 계산에 포함할지 여부는 운영 정책 기준으로 확정이 필요합니다.
- 판매내역상세 검증값과 PA+CA 판매수량 차이가 큰 SKU에 대한 업무 처리 기준을 확정해야 합니다.

## 12. 기대 효과

- 여러 CMS/ERP 파일을 수작업으로 연결하는 시간을 줄일 수 있습니다.
- SKU별 발주 판단 기준을 통일할 수 있습니다.
- EU 현지 재고, 본사 EU 창고 재고, 운송중 물량을 함께 고려한 발주 검토가 가능합니다.
- 브랜드별 발주 필요 수량과 금액을 빠르게 확인할 수 있습니다.
- 본사 이동 가능 SKU와 신규 발주 필요 SKU를 분리하여 의사결정할 수 있습니다.
- 확인 필요 SKU를 별도 시트와 플래그로 분리하여 검토 누락을 줄일 수 있습니다.
- 팀장님, BM, ESM 실무자 간 커뮤니케이션 기준을 통일할 수 있습니다.
